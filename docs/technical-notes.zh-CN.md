## 在线语音、MCP 与状态

`app_main → Application::Initialize/Run` 建立应用流程。麦克风数据由输入任务送入唤醒／音频处理与 Opus 编码队列，网络服务返回音频和 MCP 消息；播放任务消费解码后的 PCM。语音识别、对话模型、合成语音及外部点歌服务没有作为可离线复现的完整服务端随仓库发布。

实际工具名是 `self.device.set_light_mode`，参数 `mode` 范围 0–22。工具把 15 或 16 均改为 WROOM 模式 15，再通过 `Schedule` 发送换行结尾编号并设置 `is_music_mode_`。音乐分支返回请求服务端调用 `%search_music`／`%play_music` 的说明；这不是本地乐曲下载器，不能保证任意点歌成功。其他模式关闭 S3 的音乐分析标记。

WROOM 的16是黄色笑脸，但未找到S3唤醒路径自动发送`16`的处理，因此不将自动唤醒灯板反馈列为已接通。S3工具把15/16统一发送为15，拒绝17/18；接收端仅允许0–16、19–22。被注释的A2DP／`play_online_music`不计为已实现蓝牙音箱。

会话接收 `tts stop` 后，非手动模式回到 Listening；音频通道关闭则回 Idle。该行为来自客户端状态流程，不等于永久离线连续识别。语音 SDK、Opus 和 MCP 基础实现归属上游，项目扩展主要是模式工具和播放分析联动。

## 播放音频的 FFT 与可视化

### 数据来源和窗口

FFT 位于 `AudioOutputTask`，在 `codec_->OutputData(task->pcm)` 后分析同一 PCM；`OpusCodecTask` 负责解码，必要时重采样到输出采样率。当前本地、未跟踪的 `sdkconfig` 选择 `BREAD_COMPACT_WIFI`，该板型输入 16 kHz、输出 24 kHz。换用其他板型时必须重新核对输出采样率。

音乐标记开启且有 PCM 才运行分析。N=512，Hann 窗由 ESP-DSP 生成，调用复数基 2 FFT（虚部填零）与位反转后取幅值。令 s[n] 为 int16 PCM：

```math
u[n]=s[n]/32768,\quad w[n]=\tfrac12\left(1-\cos\frac{2\pi n}{N-1}\right),\quad
X[k]=\sum_{n=0}^{N-1}u[n]w[n]e^{-j2\pi kn/N}
```

先对**未加窗**的 u[n] 计算 RMS。RMS<0.005 时走静音分支。累积数据超过 1536 样本时只保留最近 1024，正常每次消耗 512；没有窗口重叠，也不保证全部样本均被分析。若输出为 24 kHz，理论窗口时长为 21.33 ms、频点间隔 46.875 Hz；均非实测计算耗时或保证的数据包频率。

### 频带、幅度与鼓点规则

边界数组为 `[1,2,3,4,5,7,9,12,16,22,30,41,56,76,103,140,200]`，每带取左闭右开区间内幅值的**平均**。忽略 DC 与 200–255，不是标准 Mel/Bark 滤波器组，也不是全 256 点等价压缩。24 kHz 下使用频点中心约 46.875–9328.125 Hz。

设 a_i 为频带平均幅值，P 为共享峰值跟踪器，初值 0.01：

```math
P_t=\max(0.98P_{t-1},\max_i a_i,0.01),\qquad
v_i=\left\lfloor15\frac{\ln(1+10a_i/P_t)}{\ln11}\right\rfloor
```

索引 13–15 的整数 v_i 再除以 2，最后限制到 0–15。索引 >=10 的乘数是 1.0，不表示额外增益。低频量 L 是频点 1–4 的**幅值和**，不是平方能量；24 kHz 时中心约 46.875–187.5 Hz。

```math
\mathrm{beat}_t=[L_t>1.3E_{t-1}]\land[L_t>0.15]\land[\mathrm{RMS}>0.015],\qquad
E_t=0.6L_t+0.4E_{t-1}
```

这是一组经验阈值的低频突增标志，不是经标注评测的节拍／BPM／鼓型识别器。不能沿用旧版的 1.45、RMS>0.08 或 0–120 Hz 描述。

### WROOM 柱形显示

有效帧需要`f,`后有beat和16个频带，共17个整数。存在非零频带时，若第0列<=1，就以`min(15,第1列+1)`补偿；beat=1时第0列为15。全零静音帧不触发首列补偿。显示包含视觉修饰，不能作为校准过的声学测量。

上升立即跟随输入，下降在每次渲染调用时采用固定步长加比例衰减；渲染由有效数据包触发，断流超过500 ms后由`tick()`每30 ms继续触发：

```math
h_i'=\begin{cases}b_i,&b_i\ge h_i\\h_i-(0.4+0.05h_i),&b_i\lt h_i\end{cases}
```

下降分支若h_i'<b_i+0.2且b_i<=2，设为b_i，再钳到非负。没有速度状态或时间步长，属于经验下落平滑。仅在`current_height>0`时绘制`y=0..current_height`、物理行`15-y`；零高度不会强制画底行，旧画面仍按衰减逐步淡出。beat叠加`CRGB(0,25,25)`，是青色分量，不是白闪。

## 坐标、模式与游戏

### 单块蛇形映射

`MatrixLayout::PixelIndex` 对越界返回 -1，普通绘图和频谱共用。原点在正视左上角，偶数行向右，奇数行向左：

```math
i(x,y)=16y+\begin{cases}x,&y\bmod2=0\\15-x,&y\bmod2=1\end{cases},\qquad 0\le x,y<16
```

例：(0,0)→0、(15,0)→15、(0,1)→31、(15,1)→16。该索引不适配课程图片的四块分块走线；不能用此公式证明历史接线正确。代码不使用查找表，但没有纳秒级性能测量。

### 实际模式表

| ID | 动作 | 入口与备注 |
| :--- | :--- | :--- |
| 0 | 清屏／待机 | 完整合法的串口或语音工具命令可立即退出音乐；不再受旧UART保护门拦截。 |
| 1/2/3 | 红／蓝／绿 | 串口或工具；人脸只发送 1/2。 |
| 4/5/6/7 | 彩虹／呼吸／流星／星点 | 5/6/7 有对应手势；效果使用 FastLED 辅助函数。 |

### 游戏机制和边界

贪吃蛇以有限空格搜索排除蛇身、保留旧尾增长、满盘结束；方向在每步一次性应用，依据上一已提交方向拒绝反向。保持450 ms初始间隔、最低80 ms、两位显示及原有方块规则，不把此修复当成性能测量。

俄罗斯方块使用 16×16 存储数组，其中 x=3..12 为 10 列场地，两侧画边界；7 类形状、各 4 个预设朝向。碰撞约束横边界、底部与已落方块。初始自动下降 800 ms，消一行 +1 分、间隔减少 30 ms，最低 100 ms；消行后重查同一行。W 旋转、S 下移一格、A/D 横移；没有墙踢、硬降或旋转插值。

结算调用 `drawGameScore`，两位字模实际只显示分数末两位。游戏初始化仅在 `currentMode != lastMode` 且进入 19/21 时执行，重复发送同一个运行中编号不会重开游戏。

## 通信与模式仲裁

S3 UART1、WROOM Serial1和Jetson Serial2使用115200 8N1；模式帧为十进制加CR/LF，频谱为 `f,beat,b0,...,b15` 加CR/LF。节拍仅0/1，频带0–15，完整通过校验后才修改显示状态。无校验和、序号、ACK或重发。

正常显示仍使用大于30 ms的提交门槛；频谱随有效输入刷新，并在断流后继续衰减。这是调度参数，不是实测帧率或硬实时保证。

| 路径 | 实际行为 | 限制 |
| :--- | :--- | :--- |
| S3 | 固定缓存、完整字段和合法模式验证，显式切模可退出音乐。 | 无硬件ACK；不会据此声称送达成功率。 |
| Jetson/USB | 同样要求CR/LF；不再以50 ms超时把部分帧当完整命令。 | 旧的不带换行发送方式必须更新。 |
| Blinker | W/S/A/D 控制运行游戏；E/F 进入游戏。 | 当前 15 时 E/F 始终拒绝；没有调色盘、完整灯效列表或退出音乐的按钮。 |

固定96字节帧限制替代 `String.reserve`，超长输入整帧丢弃。临时 `String(line)`、音频vector和第三方库仍可能分配内存，不宣称零分配。

合法频谱文本在 beat 为一位且频带 0–15 时约 36–52 字节；8N1 线速序列化约 3.13–4.51 ms，尚不包括处理和排队，不能当作端到端实测。FastLED 的 5 V/1200 mA 是库估算的功率预算，不是实测电流、物理稳流器或电源额定参数。
