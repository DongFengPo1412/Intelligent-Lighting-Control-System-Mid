## オンライン音声・MCP・状態

`app_main → Application::Initialize/Run`が起動経路です。入力タスクはマイクをウェイク検出・音声処理・Opus符号化へ渡し、ネットワークサービスから音声とMCPメッセージを受けます。再生側は復号済みPCMを消費します。認識・対話・合成・楽曲サービスの完全なオフライン再現用サーバーは同梱されていません。

実ツール名は`self.device.set_light_mode`、整数`mode`は0–22です。15と16は共にWROOMの15へ変換し、`Schedule`で改行付き番号を送り、`is_music_mode_`を設定します。音楽分岐はサーバーに`%search_music`／`%play_music`を要求する説明を返すもので、ローカル楽曲ダウンローダーではなく、任意の楽曲再生を保証しません。他モードはS3の音楽解析を停止します。

WROOMの16は黄色い笑顔ですが、S3のウェイク経路から`16`を自動送信する処理は確認できません。LED上の自動ウェイク応答が接続済みとは扱いません。17/18は引数として通りますが、描画実装はありません。コメントアウトされたA2DP／`play_online_music`はBluetoothスピーカーの完成機能に含めません。

`tts stop`後、手動以外の会話はListeningへ戻り、音声チャネルが閉じるとIdleへ戻ります。これはクライアントの状態遷移で、永続的なオフライン連続認識ではありません。音声SDK、Opus、MCPの基盤は上流の実装であり、プロジェクト拡張は主にモードツールと再生解析の連携です。

## 再生音のFFTと可視化

### 入力と窓

FFTは`AudioOutputTask`内の`codec_->OutputData(task->pcm)`後に同じPCMを解析します。`OpusCodecTask`が復号し、必要時に出力レートへ変換します。追跡対象外のローカル`sdkconfig`は`BREAD_COMPACT_WIFI`を選び、この設定は入力16 kHz・出力24 kHzです。他のボードでは出力レートの再確認が必要です。

音楽フラグとPCMがある場合に実行します。N=512、ESP-DSPのHann窓と、虚部ゼロの複素基数2 FFT・ビット反転・振幅を用います。int16 PCMをs[n]とすると：

```math
u[n]=s[n]/32768,\quad w[n]=\tfrac12\left(1-\cos\frac{2\pi n}{N-1}\right),\quad
X[k]=\sum_{n=0}^{N-1}u[n]w[n]e^{-j2\pi kn/N}
```

RMSは**窓を掛ける前**のu[n]から計算し、0.005未満で無音分岐へ進みます。1536サンプルを超えると最新1024だけを残し、通常は512ずつ消費します。窓の重複はなく、全サンプル解析の保証もありません。24 kHzで窓長は理論上21.33 ms、周波数間隔は46.875 Hzですが、実測計算遅延や保証された送信頻度ではありません。

### 帯域・振幅・ビート規則

境界は`[1,2,3,4,5,7,9,12,16,22,30,41,56,76,103,140,200]`で、各半開区間の**振幅平均**を取ります。DCと200–255は使わず、標準Mel/Barkフィルタバンクでも全256点の圧縮でもありません。24 kHzでは使用ビン中心は約46.875–9328.125 Hzです。

帯域平均をa_i、共通ピークをP（初値0.01）とすると：

```math
P_t=\max(0.98P_{t-1},\max_i a_i,0.01),\qquad
v_i=\left\lfloor15\frac{\ln(1+10a_i/P_t)}{\ln11}\right\rfloor
```

13–15番の整数値をさらに2で割り、0–15に制限します。10番以上の係数1.0は追加利得ではありません。低域量Lは1–4番ビンの**振幅和**で、二乗エネルギーではなく、24 kHzで中心約46.875–187.5 Hzです。

```math
\mathrm{beat}_t=[L_t>1.3E_{t-1}]\land[L_t>0.15]\land[\mathrm{RMS}>0.015],\qquad
E_t=0.6L_t+0.4E_{t-1}
```

経験的な低域の急増フラグで、評価済みの拍・BPM・ドラム分類器ではありません。旧版の1.45倍、RMS>0.08、0–120 Hzは実装と一致しません。

### WROOMの棒グラフ

有効フレームは`f,`の後にbeatと16帯域、計17整数が必要です。0列目が<=1なら1列目+1に置き換え、beat=1なら15にします。見栄えの補正を含み、校正済みの音響測定ではありません。

上昇は入力へ即時追従し、下降は**受信パケットごとの描画**で固定量と比例量を引きます：

```math
h_i'=\begin{cases}b_i,&b_i\ge h_i\\h_i-(0.4+0.05h_i),&b_i<h_i\end{cases}
```

下降でh_i'<b_i+0.2かつb_i<=2ならb_iに戻し、最後に非負へ制限します。常にゼロへ戻す処理ではありません。速度状態も時間刻みもないため、重力・空気抵抗の物理シミュレーションではなく経験的な下降平滑化です。`y=0..int(h_i)`、物理行`15-y`で描くため、ゼロでも最下行の画素は描きます。beat時は`CRGB(0,25,25)`を加算し、白ではなくシアン成分です。

## 座標・モード・ゲーム

### 1枚パネルの蛇行変換

`MatrixLayout::PixelIndex`は範囲外を-1とし、通常描画とスペクトルで共有します。正面の左上を原点とし、偶数行は右向き、奇数行は逆方向です：

```math
i(x,y)=16y+\begin{cases}x,&y\bmod2=0\\15-x,&y\bmod2=1\end{cases},\qquad 0\le x,y<16
```

例：(0,0)→0、(15,0)→15、(0,1)→31、(15,1)→16。授業写真の4枚の分割配線とは異なり、旧配線の正しさを証明しません。テーブルは使いませんが、ns単位の速度測定はありません。

### 実際のモード

| ID | 動作 | 入口と注意点 |
| :--- | :--- | :--- |
| 0 | 消灯・待機 | シリアル／音声ツール。S3経路の抑制で一時拒否される場合あり。 |
| 1/2/3 | 赤／青／緑 | シリアル／ツール。顔は1/2のみ送信。 |
| 4/5/6/7 | 虹／呼吸／流星／星 | 手は5/6/7に対応。FastLEDの補助関数を使用。 |
| 8/9/10 | 全面色変化／ランダム雨／波紋 | 8は一様HSV、9は乱数画素、半径計算は10のみ。 |
| 11/12/13/14 | 笑顔／泣き顔／無表情／交互表情 | 円と固定の目・口。14は色相に応じて笑／泣を切替。 |
| 15 | スペクトル | パケットで更新。15の送信だけでは音は発生しません。 |
| 16 | 黄色い笑顔 | WROOM側の定義。S3ツールの16は15へ変換。 |
| 19/20 | スネーク／得点 | Eまたはツール19。自身衝突で20へ。 |
| 21/22 | テトリス／得点 | Fまたはツール21。生成時の衝突で22へ。 |
| 17/18、その他 | 未定義 | 完成機能に数えません。受信側に厳格な許可リストはありません。 |

### ゲーム処理と制約

スネークは長さ256のx/y配列、初期長3、初期間隔450 msを`millis()`で更新します。食物で1点増え、間隔は`max(80,450-15*score)`です。頭座標をmod 16で折り返し、自身衝突で終了します。方向コールバックは現在方向への直接逆行を防ぎますが、移動前の連続入力は要検証です。食物は身体を除外せず、成長時に旧尾座標を新要素へ明示コピーしません。Basicの食物除外機能をMidに帰属させません。

テトリスは16×16配列のx=3..12を10列の盤面とし、左右に壁を描きます。7形状に各4つの保存回転を持ち、横境界・床・固定ブロックを検査します。初期落下800 ms、行消去ごとに1点、30 ms短縮、下限100 msです。行を詰めた後は同じ行を再検査します。W回転、Sは1マス下降、A/D横移動で、壁蹴り・ハードドロップ・回転補間はありません。

`drawGameScore`は実質的に末尾2桁を描画します。初期化は`currentMode != lastMode`で19/21へ入る時のみなので、実行中に同じ番号を送っても再開始しません。

## Jetsonの視覚イベント

操作風景であり、認識ウィンドウや計時を示さず、精度・判定出力・30 FPSの証拠ではありません。

- [run_gesture.py](../jetson-nano-py36/run_gesture.py)：MediaPipe Handsで片手を検出。親指はx、他は指先と関節のyを比較し、指本数0–5を送信。

- `face_system_cn.py`：Haar検出、グレースケール100×100、OpenCV LBPH学習・予測。起動時とTで全画像から再学習し、Sで最初の顔を入力名のディレクトリへ保存、Qで終了します。`conf<80`は距離の閾値で、80%の確率ではありません。`ylk→1`は赤、`zzc→2`は青です。ローカルガイドの「2は緑」は旧記述です。
- [face_system.py](../jetson-nano-py36/face_system.py)：既定は画面なし、閾値95、毎回0.05 sの追加待機があり、登録キーはありません。前者と完全に同じ代替ではありません。
- [face_pyserial.py](../jetson-nano-py36/face_pyserial.py)：旧登録版で、統一ROIサイズなど後の処理がありません。`pickle`と`DATA_FILE`はモデル保存を実装していません。

`recognizer.update`やモデル保存はなく、オンライン増分学習ではありません。追跡対象は`faces/ylk/.gitkeep`と`faces/zzc/.gitkeep`のみで、顔画像や学習済みモデルは配布しません。主要スクリプトは同じカメラと`/dev/ttyTHS1`を使うため個別実行とし、プロセス間調停はありません。推論はMediaPipeのライブラリが行い、CUDA使用を示すコードはありません。

## 通信とモード調停

S3 UART1–WROOM Serial1、Jetson–WROOM Serial2は115200・8N1です。モードは10進数と改行、スペクトルは`f,beat,b0,...,b15\n`です。チェックサム、連番、ACK、再送はありません。逆向きピンは設定されていますが、アプリの心拍・状態確認送信はありません。

通常表示は`millis()-lastShow>30`、音楽ではこれを通らず各受信パケットで`FastLED.show()`を呼びます。Blinker、S3、Jetson、USBを順次処理するループで、ハードリアルタイムの根拠はありません。

| 経路 | 実際の動作 | 制約 |
| :--- | :--- | :--- |
| S3 | CR/LFで区切り、15かつ最新fから1200 ms未満なら他モードを拒否。非ゼロ後4000 ms以内は0も拒否され得ます。 | この経路だけの保護。50 msタイムアウトなし。`toInt`は不正文字を0にできます。 |
| Jetson/USB | 数字確認、CR/LFまたは最終バイト後>50 msで解析。 | タイムアウトは残フレームを処理し、検証後破棄ではありません。音楽ロックも許可モード一覧もなし。 |
| Blinker | W/S/A/Dでゲーム、E/Fで開始。 | 15ではE/Fを常に拒否。色選択・全効果メニュー・音楽終了ボタンなし。 |

`String.reserve(128)`は予約容量で、上限ではありません。文字列は拡張可能で、PCMにもvectorを使うため、動的割当てゼロ・断片化ゼロ・産業品質とは主張しません。

beatが1桁、帯域0–15なら有効なスペクトル文は約36–52バイトです。115200・8N1で線上の送信時間は約3.13–4.51 msですが、処理・待ち行列を含まない理論値で、実測遅延ではありません。FastLEDの5 V/1200 mAは推定ソフトウェア電力予算で、実測電流、物理的な定電流回路、電源定格ではありません。

今回確認したのは静的な呼出し・設定・ファイル差分です。実機、ファームウェアビルド、学習、全経路試験は未実施です。過去の動画・写真・ガイドは授業時の背景を示し、現行改版の全機能を検証しません。

PPTは刘超然、张子琛、杨立科と広い担当を示しますが、Bluetooth、筐体、構成の説明は現存実装と完全には一致しません。本書はチーム成果を扱い、個人別のモジュール作者は追加確認が必要です。第三者フレームワークの能力を個人の独創的成果とは扱いません。
